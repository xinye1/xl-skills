**Constraints and intent, not a procedure. You own the orchestration plan: decompose, sequence, parallelise, and verify as you judge best. These constraints are fixed:**

- **Delegate execution; keep judgement.** Task execution goes to subagents by default — the intent is that your own context stays at integration level for the whole phase; that hygiene is why this chat exists. On long runs most of your input bills as cache reads, so a lean context matters more the bigger your own model is. Spawn in proportion to the work: batch sub-trivial tasks at the same dependency position into one subagent rather than one each, and keep verification in your own loop, not in extra subagents. Run overall integration validation (full tests, lint, types, any E2E the exit criteria name) yourself — never delegate it, and never ship on task-level test reports alone.
- **Size each task to one working context, and checkpoint anything long.** A subagent's cost grows with the *square* of its length — every tool call re-reads its whole accumulated context, so a 600-call agent costs ~4× a 300-call one. Split a task that would have an agent grinding on the same large artifact for hours; the tell of an oversized task is late calls carrying >500k tokens and returning almost nothing. Any subagent expected to run beyond ~30 minutes must write progress to a durable file as it goes, named in its prompt, so a kill (usage limit, crash, interrupt) costs minutes rather than its whole unrecoverable context.
- **Size each subagent's model to its task and pass it explicitly.** `haiku` for read-and-report work where a wrong answer is cheap to spot (finding files, reading logs, running a known command and reporting, summarising), never for code edits or judgement calls. `sonnet` (the default) for standard implementation against a clear spec. `opus` for high-ambiguity or high-stakes tasks. `fable` only for frontier-hard tasks. Input list prices are Haiku 5.5 $0.10 (prompts up to 100K tokens, $0.50 above), Sonnet 5.5 $2, Opus 5.5 $4 and Fable 5.2 $8 per MTok; the source of truth is `summarise-session/references/prices.json`. Every tier must earn its premium: on one heavy day, 1,944 `sonnet` task-subagent calls cost ~$77 total and 2,900 `opus` calls cost ~$734. On a genuine boundary pick the higher tier, because a cheap wrong answer redone on a bigger model costs double. The built-in Explore subagent runs on your own model, so dispatch cheap exploration with `model: haiku` explicitly.
- **Escalate a falling-short subagent in order: verification, then effort, then tier.** Pass `effort: medium` explicitly to start; left out, a subagent inherits your own session's effort. When a subagent falls short, first give it a way to check its own work (a test, a build, a script), then retry one effort level higher, then move up one tier at `medium`. Past `high`, the next tier usually beats `xhigh` or `max`. For many auto-checkable tasks, run them at `low` and re-run only the failures at `high`.
- **Subagent prompts are self-contained** — plan path, branch, guardrails, and a definition of done that includes the tests the subagent must run and pass before reporting back. Each subagent follows `superpowers:executing-plans` internally. A red-tested task is not a completed task. Where the deliverable genuinely has no executable test — a plan, a spec, a prose document — say so explicitly in the prompt and name the standing checks instead (self-review checklist, placeholder scan, citation audit). That substitution is about the deliverable's *type*, never about a task being awkward to test; anything producing code has an executable test by definition.
- **A drafted decomposition needs user sign-off.** If the plan lacks an explicit task list for this phase, validate the task list you derive with the user before dispatching anything.
- **Steer at outcome level.** The user cares that exit criteria are met, not about step approval. Interrupt them only for decisions that are genuinely theirs — scope changes, destructive actions, ambiguity in the plan's intent.
